# 방문자 통계 DB 마이그레이션 - 요구사항

## 문제 상황

### 기존 시스템의 한계
1. **localStorage 기반 통계**
   - 브라우저별로 독립적인 데이터 저장
   - 브라우저를 바꾸면 통계가 초기화됨
   - 관리자가 다른 브라우저에서 접속하면 통계가 0으로 보임

2. **두 시스템의 분리**
   - 홈페이지 위젯: `visitor_history` localStorage 사용
   - 관리자 페이지: `visitor_stats` DB 사용 (하지만 데이터가 없음)
   - 기존 방문 데이터가 관리자 페이지에 표시되지 않음

3. **관리자 페이지의 목적**
   - 관리자 자신의 방문 통계가 아님
   - **일반 방문객의 전체 방문 통계**를 보기 위한 것
   - 현재는 데이터가 없어서 의미 없는 상태

## 해결 방안

### localStorage + DB 하이브리드 방식
- **일반 방문자**: localStorage에 즉시 저장 (지연 없음) + DB에 비동기 저장
- **관리자**: DB에서 전체 통계 조회
- **성능**: 사용자는 렉 없이 즉시 페이지 로드, DB 저장은 백그라운드 처리

### 성능 고려사항
- 10년 데이터 = 87,600행 (365일 × 24시간 × 10년)
- 인덱스로 조회 속도 ~10ms (매우 빠름)
- 이벤트 데이터(~5,000행)보다 빠름

## 요구사항

### 1. DB 테이블 생성
- `visitor_stats` 테이블 생성
- 필드: `visit_date`, `visit_hour`, `visit_count`
- 인덱스: 빠른 조회를 위한 날짜/시간 인덱스
- RLS 정책: 읽기는 모두 가능, 쓰기는 인증된 사용자

### 2. 방문 기록 로직 수정
- localStorage에 즉시 저장 (동기, 지연 없음)
- DB에 비동기 저장 (await 없음, 백그라운드)
- UPSERT 로직: 같은 날짜/시간이면 count 증가

### 3. 기존 데이터 마이그레이션
- `visitor_history` localStorage 데이터를 DB로 이전
- 한 번만 실행 (플래그로 중복 방지)
- 자동 실행: 앱 시작 시 자동으로 마이그레이션

### 4. 관리자 페이지 수정
- DB에서 통계 조회 (async/await)
- 전체 방문자 통계 표시
- 실시간 업데이트 (1분마다)

### 5. 성능 요구사항
- 일반 사용자: 페이지 로드 시 렉 없음
- DB 저장 실패 시: 사이트는 정상 작동 (통계만 누락)
- 관리자 페이지: 통계 조회 속도 ~10ms 이내

## 기대 효과

1. **통합된 통계 시스템**
   - 모든 방문자 데이터가 DB에 저장됨
   - 관리자는 어떤 브라우저에서든 전체 통계 확인 가능

2. **성능 유지**
   - 일반 사용자는 렉 없이 즉시 페이지 로드
   - DB 저장은 백그라운드에서 처리

3. **데이터 보존**
   - 기존 localStorage 데이터 자동 마이그레이션
   - 브라우저를 바꿔도 통계 유지

4. **실시간 통계**
   - 새벽 배치 작업 필요 없음
   - 사용자 방문 시마다 DB에 즉시 저장됨
